# Bringup Isolation Tests

**Author:** Hongyi Mei
**Date:** 2026-07-28

---

These staged tests were used during Phase 5 to isolate the boot-loop
failure encountered when integrating TFLite Micro with the ESP32-S3-CAM.

All tests target the **ESP32-S3-WROOM-1 N16R8** module and are built with
**PlatformIO** (Arduino framework). Each `platformio.ini` includes the
critical N16R8 board settings: 16 MB flash, octal PSRAM (`qio_opi`), and
the `default_16MB.csv` partition table.

## Tests

### T1 — Board Configuration Validation

**Purpose:** Verify that the N16R8 module is configured correctly —
flash size (16 MB), octal PSRAM initialized (8 MB), and PSRAM data
integrity via a 1 MB write/read pass.

**How to run:**
```bash
cd firmware/bringup/t1_board_config
pio run --target upload && pio device monitor
```

**Expected output:**
```
Flash size    : 16777216 bytes
PSRAM found   : YES
PSRAM total   : ~8386279 bytes
PSRAM write/read: PASS
Largest DRAM  : ~335860 bytes
```

---

### T2 — Camera-Only Capture

**Purpose:** Confirm the OV2640/OV3660 camera driver initializes and
captures 96 × 96 RGB565 frames (18 432 bytes each) with no TFLite code
linked. Monitors heap levels across frames to detect frame-buffer leaks.

**How to run:**
```bash
cd firmware/bringup/t2_camera_only
pio run --target upload && pio device monitor
```

**Expected output:** Sensor PID printed (e.g., `0x3660` for OV3660),
frames with `len=18432 (OK)`, and stable DRAM/PSRAM free values across
frames. The `sum64` field is a cheap liveness check — a constant value
across frames means the sensor is not actually streaming.

---

### T3 — TFLite Isolation (No Camera)

**Purpose:** Load the INT8 model into TFLite Micro with an oversized
arena (160 KB), allocate tensors, and measure actual arena usage. Runs
inference on synthetic (constant-fill) input to verify the model
executes and produces varying output.

**How to run:**
```bash
cd firmware/bringup/t3_tflite_only
pio run --target upload && pio device monitor
```

**Expected output:**
```
arena addr   = 0x3fc96bfc  (SRAM)
ARENA USED   = 103552 / 163840 bytes  (63.2%)
input  dims  = [1,96,96,3] INT8
input  quant = scale 0.003922, zero_point -128
operators    = 10
Invoke       ≈ 4.15 s
```

**Note:** The 160 KB arena is deliberately oversized. The measured
103 552 B usage informed the production arena size of 120 KB in T4.

---

### T4 — Camera + INT8 Inference

**Purpose:** Full integration — capture a 96 × 96 RGB565 frame, convert
RGB565 to INT8 (channel − 128), run inference, and print the
occupied/empty classification with timing breakdown.

**How to run:**
```bash
cd firmware/bringup/t4_camera_tflite
pio run --target upload && pio device monitor
```

**Expected output:**
```
Model ready | arena 103552/122880 | quant scale 0.003922 zp -128
#1 [OCCUPIED] empty= -42 occ=  15 | conv 850 us, infer 4150 ms | dram=... psram=...
```

**Key details:**
- Arena: 120 KB allocated, 103 552 B used.
- RGB565→INT8 conversion: pixel values mapped via `(channel_uint8) − 128`,
  matching the quantization parameters (scale ≈ 1/255, zero_point = −128).
- Frame buffer is returned to the camera driver *before* the multi-second
  `Invoke()` call to avoid holding PSRAM during inference.
- Inference runs every 10 s (`INFER_PERIOD`).

## Dependencies

T3 and T4 require `parking_model.h` (the INT8 model as a C array) in
their `src/` directory. This header is generated by the training notebook
(`model/training/colab.ipynb`, Cell 10).

The TFLite library is pulled automatically by PlatformIO from
[tanakamasayuki/Arduino_TensorFlowLite_ESP32](https://github.com/tanakamasayuki/Arduino_TensorFlowLite_ESP32)
(declared in `platformio.ini` via `lib_deps`).

**版本:** v0.1 (MVP)
**作者:** Hongyi Mei

---

## 0. 一句话概述

三个摄像头对着一个停车位。屏幕上一个方块，有车变红、没车变绿，下面写着 `2/3`，表示三票里两票认为有车。方块上方显示已经停了多久。

页面下半部分是过去 10 小时的时间轴，看得出什么时候有车、什么时候没车，旁边列出每次停车的起止时间和时长。

最下面三行，每行一个摄像头节点，显示在线还是离线、最后一次上报是什么时候。拔掉一个节点的电，那一行变灰，上面的票数从 `2/3` 变成 `2/2`。

以下是细节。

---

## 1. 背景

三个 ESP32-S3 摄像头节点对同一个停车位做占用检测，各自通过 MQTT 上报判断结果。
网关（Raspberry Pi）对三票做多数表决，得出权威占用状态，并写入 SQLite。

**你负责的部分：** 从 SQLite 往后的一切 —— 读库、API、前端页面。
**你不需要碰的部分：** MQTT、节点固件、融合算法。数据库对你而言是只读的。

采用多数表决的原因是单个视觉节点会误判。仿真中单节点准确率 85%、三节点融合 94%
（85% 是模拟器写死的注入误判率，94% 是三取二表决的算术结果，用来验证表决逻辑正确，
不代表真实分类器的表现）。真实分类器在部署环境下的准确率**尚未测得**。
因此 UI 需要能体现「这一票是 3/3 一致，还是 2/3 险胜」的差别。

---

## 2. Demo 场景

现场只有**一个车位（车位 A）**。演示流程大致是：

1. 车位空着 → 页面显示绿色 / 空闲
2. 放一个模型车进去 → 几秒内页面变红 / 占用，开始计时
3. 拔掉其中一个节点的电源 → 页面提示该节点离线，投票变成 2 票制
4. 把车拿走 → 页面变回空闲，本次停车时长进入历史列表

## 3. 功能需求

### 3.1 实时状态（必做）

- 车位 A 当前是 **占用 / 空闲**，用颜色明确区分
- 显示本轮表决票数，例如 `2/3` 或 `3/3`
- 当票数分母小于 3（有节点失联）时，需有视觉提示，不能和正常状态混淆
- 若当前为占用状态，显示**已停时长**（从本次占用开始至今）
- 刷新频率 3–5 秒即可，轮询或 SSE 都行，不要求 WebSocket

### 3.2 历史视图（必做）

- 展示**过去 10 小时**车位 A 的占用变化
- 形式不限：时间轴条带、折线、表格都可以，能看出「什么时候有车、什么时候没车」即可
- 附一个本次窗口内的**停车会话列表**：开始时间、结束时间、时长

### 3.3 节点健康（必做）

- 列出 3 个节点，各自显示 **在线 / 离线**
- 显示每个节点最后一次上报的时间
- 离线节点需要明显标记

### 3.4 明确不做（MVP 范围外）

- 计费、费率、支付
- 超时告警、违停判定
- 用户注册、车辆识别、车牌
- 多车位管理
- 登录鉴权
- 移动端适配（桌面浏览器能看即可）

## 4. 数据来源

SQLite 文件位于树莓派上（路径待定，部署时给你）。
已开启 WAL 模式，你的读取不会被写入阻塞。

**表结构见 `schema.sql`。** 几个使用要点：

| 需求 | 数据来源 |
|------|----------|
| 实时状态 | `fused` 表按 `ts` 取最新一行 |
| 票数显示 | `fused.votes_occ` / `fused.votes_total` |
| 历史视图 | `fused` 表按 `ts` 范围查询 |
| 停车会话 | `sessions` 表，`ended_at IS NULL` 表示进行中 |
| 已停时长 | 当前时间 − `sessions.started_at` |
| 节点健康 | `nodes` 表（当前状态 + 最后上报时间） |

`readings` 表是三个节点的原始上报，MVP 阶段**不需要展示**，保留是为了后续分析单节点可靠性。

**时间格式统一为 unix epoch 秒（UTC）**，前端负责转成本地时间显示。

## 5. 技术约定

- 后端语言/框架你定，Flask 或 FastAPI 都行
- 前端不要求框架，原生 HTML/JS 足够
- 部署在树莓派本机，通过局域网 IP 访问
- 数据库连接请以只读方式打开（`file:...?mode=ro`），避免误写
